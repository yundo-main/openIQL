# 법률 리스크 검토 노트

> **면책**: 이 문서는 법률 자문이 아니며, 프로젝트의 기술적 리스크 관리 기록입니다.
> 상용 배포 전 반드시 변호사·변리사의 정식 검토(FTO, Freedom-to-Operate)를 받으십시오.

- **최초 검토일**: 2026-11-25
- **검토 범위**: 저작권, 의존성 라이센스, 상표, 특허(미국/중국 공개 DB)
- **검토 도구**: Google Patents, 웹 검색. USPTO PatentCenter 정식 조사 아님.

---

## 1. 저작권 — 위험 없음 (조치 완료)

- 전 코드는 `spec/grammar.ebnf` 자체 명세로부터 독자 구현(클린룸). 상용 제품의
  바이너리·디컴파일 코드·원본 문법 파일 미참조 — `CONTRIBUTING.md`에 원칙 명문화.
- 쿼리 언어 문법·연산자·함수명 같은 기능적 요소는 일반적으로 저작권 보호 대상이 아님.
  선행기술(SQL 1974~, Lucene syntax, KQL, GraphQL 등) 다수 존재.
- **유지 조건**: 기여자가 외부 문법 자료를 참조해 복제하지 않도록 DCO 서명
  (`git commit -s`) + `npm run check:dco` + CI 검증으로 모든 커밋의 독자 작성 보증 추적.

기여자발 특허 리스크에 대한 내재 방어로 작동.

## 3. 상표 — 낮음

- 독자 명칭 `OpenIQL` 및 독자 API 규격(`?q=`, `?filter=`) 사용 — 상용 제품 상표와 혼동 방지 설계.
- **주의**: 문서·마케팅에서 타사 상표(제품명, 쿼리 언어명)를 비교 목적 외로 사용하거나
  공식 제품처럼 오인시키는 표현 금지.

## 4. 특허 — 알려진 활성 특허와 청구항 불일치 확인

2026-11-25 기준 공개 DB 검색 결과, 본 프로젝트의 핵심 기능(텍스트 쿼리 → AST →
DB/검색엔진 트랜스파일)과 독립 청구항이 겹치는 특허를 발견하지 못함.

- 본 프로젝트의 `CHANGED`는 `FROM`/`TO`만 지원 — 외부 쿼리 언어의
  `BY`/`AFTER`/`DURING`/`ON` 술어를 미구현한 독자 명세로, 기능 차별화 존재.

### 잔여 리스크 (클린룸으로 제거 불가)

- **비공개 계류 출원**: 출원 후 18개월간 검색 불가.
- **독자 개발은 특허 항변 사유가 아님**: 저작권과 달리 클린룸 증빙은 특허 침해 방어에 무효
  (고의성 가중배상 완화에만 참작).
- **특허괴물(NPE)**: 양수인 무관하게 범용 "구조화 쿼리" 특허로 공격 가능 — 모든 SW 공통 리스크.
